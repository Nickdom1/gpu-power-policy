# Prior art and related work

Related implementations and earlier observations.

| Project | What it does | Platform | Relation |
|---|---|---|---|
| **@pantsoftime, `vbios_override`** ([credit in Panchovix's release](https://github.com/Panchovix/nvidia-windows-vbios-vix-loader/releases/tag/v0.3.1)) | Original VBIOS override work credited by Panchovix | — | Precursor to Panchovix's loaders |
| **Panchovix: [nvidia-vbios-vix-editor](https://github.com/Panchovix/nvidia-vbios-vix-editor), [nvidia-linux-vbios-vix-loader](https://github.com/Panchovix/nvidia-linux-vbios-vix-loader), [nvidia-windows-vbios-vix-loader](https://github.com/Panchovix/nvidia-windows-vbios-vix-loader)** (2026-10-14 to 10-17) | Offline VBIOS editor (power-policy table, clocks, fans) and loaders that hand the edited image to the driver: a patched open module on Linux (driver 615+, via `vbiosOverrideArgs`), a registry value on Windows | Linux (desktop Blackwell / Ada tested), Windows | Same idea for board power as this project's boot-time edit, published first. Different driver generation and transport (this project: 595.99.02, registry `vbios` key, kernel-side edit of the card's own image). Their editor exposes the Ampere current policy but marks it read-only as "enforcement unproven"; this project shows it is enforced and binding on the tested board |
| **[amagicai/nvpowerd-boost](https://github.com/amagicai/nvpowerd-boost)** (2026-10-17) | `LD_PRELOAD` on `nvidia-powerd` rewriting the Dynamic Boost target | Linux, RTX 50 laptop | Same technique as this project's filter, published first |
| **[pablo906/NvTgpHold](https://github.com/pablo906/NvTgpHold)** (2026-10-12) | Registry patch of the Board-Power maximum (`romOverride00`) plus a reasserted Dynamic Boost value | Windows, RTX 50 laptop | Board power only; no current policy |
| **NvpwrControl / NvpwrAIO** ([LevinAi-arch](https://github.com/LevinAi-arch/rtx-5070ti-laptop-160w-power-limit), [duanyunlun/NvpwrAIO](https://github.com/duanyunlun/NvpwrAIO); 2026-09) | Kernel-memory patching of the Windows driver's policy objects; later versions use a registry patch | Windows, RTX 50 laptop | Board power; closed source in later versions |
| **[Skyworks-Neo/nvoc](https://github.com/Skyworks-Neo/nvoc)** (2026-10) | Runtime current-limit setter through the same driver control, within the advertised maximum | Windows and Linux | Identifies the same policy (13) on Ada/Ampere; cannot exceed the table maximum, which is what the envelope image here changes |
| **[mVolt+](https://github.com/b00nz/mVolt/blob/main/docs/guide.md#bios-override)** | No-flash BIOS overrides, including NVVDD/MSVDD current limits | Windows | The guide reports raised NVVDD limit readback on an RTX 5090; load behavior for that test is unconfirmed |
| **[Thermetery/Druta](https://github.com/Thermetery-Technology-Co-Limited/Druta)** (date not recorded; GPL-3.0) | Current-limit research and I²C regulator control | Windows, desktop | Its published field offsets for the same power-policy controls on other cards were used to cross-check this project's control layouts. Offsets and names only; no Druta code is used |
